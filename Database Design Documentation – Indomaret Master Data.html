Database Design Documentation

Indomaret Master Data API — Province, Branch & Store Management
Prepared by: Caleb Dinoto  |  Date: October 2026  |  Database: MySQL (db_indomaret)

1. Overview

The db_indomaret database manages master data for Indomaret's provincial distribution network. It stores information about provinces, branches (cabang) within each province, and stores (toko) assigned to each branch. A separate users table handles authentication.

Key design decisions:
• Soft-delete — rows are never physically removed; instead is_deleted = 1 and is_active = 0 flags mark them as logically deleted. This preserves history and supports audit requirements.
• Audit trail — every mutable table carries created_by, created_at, updated_by, and updated_at columns so that every change can be traced to the authenticated user who performed it.
• Whitelist flag — stores flagged with is_whitelisted = 1 are always returned in search results regardless of province filter, enabling cross-province visibility for priority outlets.

4. Relationships Between Tables

RelationshipTypeFK ColumnDescription
provinces → branches One-to-Many (1:N) branches.province_id One province contains many branches. A branch must belong to exactly one province.
branches → stores One-to-Many (1:N) stores.branch_id One branch manages many stores. A store must belong to exactly one branch.
users Standalone — No foreign key relationship. Used solely for authentication via Spring Security.
Cascade behaviour (soft-delete):
When a branch is soft-deleted (DELETE /api/branches/{id}), its is_deleted and is_active flags are updated. The stores that belong to that branch are automatically excluded from all store search results because the query also filters by b.is_deleted = false. No physical rows are ever deleted.

5. Constraints & Indexes

PRIMARY KEY provinces(id)
PRIMARY KEY branches(id)
PRIMARY KEY stores(id)

-- Foreign Keys
CONSTRAINT fk_branch_province  FOREIGN KEY branches(province_id) REFERENCES provinces(id)
CONSTRAINT fk_store_branch     FOREIGN KEY stores(branch_id) REFERENCES branches(id)
