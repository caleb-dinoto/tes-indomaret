API Documentation

Indomaret Master Data API — Province, Branch & Store Management
Prepared by: Caleb Dinoto  |  Date: October 2026  |  Base URL: http://localhost:8080

1. Overview

This document describes all REST API endpoints for the Indomaret Master Data service. The API manages provinces, branches, and stores data with support for soft-delete, audit trails, and cross-province whitelist visibility.

PropertyValue
Base URLhttp://localhost:8080
ProtocolHTTP/1.1
Data FormatJSON (Content-Type: application/json)
AuthenticationHTTP Basic Auth (username + password)
FrameworkSpring Boot 4.1.1 / Java 17

2. Authentication

Every /api/** endpoint requires authentication. Unauthenticated requests receive HTTP 401 Unauthorized.

Use HTTP Basic Authentication: include an Authorization header with the value Basic <base64(username:password)>.

Default credentials (seeded by db_init.sql):
Username: admin    Password: password123

curl example:
curl -u admin:password123 http://localhost:8080/api/stores
Passwords are stored as BCrypt hashes in the users table. The system uses Spring Security with a custom UserDetailsService to validate credentials against the database.

3. Standard Response Format

All responses follow a consistent wrapper structure:

{
  "status":  200,          // HTTP-like status code
  "message": "...",       // Human-readable result message
  "data":    { ... }      // Payload (object, array, or null)
}
HTTP CodeMeaning
200Success
401Unauthorized — missing or invalid credentials
404Resource not found (or already soft-deleted)
500Internal server error (unexpected)

DELETE /api/branches/{id}
Soft-deletes a branch — data is NOT physically removed from the database. Sets is_deleted = true, is_active = false, records deleted_at timestamp, and sets updated_by to the authenticated user. Soft-deleted branches (and their stores) no longer appear in any API responses.
Path Parameters
ParameterTypeRequiredDescription
idIntegerYesBranch ID to soft-delete
Sample Response — 200 OK
{
  "status": 200,
  "message": "Branch berhasil dihapus (soft-delete)",
  "data": null
}
Error Response — 404 Not Found
{
  "status": 404,
  "message": "Cabang tidak ditemukan!",
  "data": null
}

7. Store Endpoints

GET /api/stores
Returns active, non-deleted stores. Supports optional province name filtering (case-insensitive partial match). Whitelisted stores (is_whitelisted = true) always appear regardless of the province filter, ensuring cross-province visibility for priority outlets. Only stores belonging to active, non-deleted branches and provinces are included.
Query Parameters
ParameterTypeRequiredDescription
provinceStringNoProvince name filter (partial match). Omit or leave empty to return all active stores.
Sample Request
GET /api/stores?province=Jakarta
Sample Response — 200 OK
{
  "status": 200,
  "message": "Berhasil mengambil data toko",
  "data": [
    {
      "id": 1,
      "name": "Indomaret Thamrin",
      "isActive": true,
      "isDeleted": false,
      "isWhitelisted": false,
      "branch": {
        "id": 1,
        "name": "Cabang Jakarta Pusat",
        "province": { "id": 1, "name": "DKI Jakarta" }
      },
      "createdAt": "2026-10-03T10:00:00",
      "updatedBy": null
    },
    {
      "id": 5,
      "name": "Indomaret Simpang Lima",
      "isWhitelisted": true,
      "branch": {
        "name": "Cabang Semarang",
        "province": { "name": "Jawa Tengah" }
      },
      // ^ whitelisted store from a different province — still returned
    }
  ]
}
Business Logic

The underlying JPQL query is:

WHERE (province.name LIKE '%:provinceName%' OR store.isWhitelisted = true)
  AND store.isActive = true  AND store.isDeleted = false
  AND branch.isActive = true AND branch.isDeleted = false
  AND province.isActive = true AND province.isDeleted = false
PUT /api/stores/{id}/whitelist
Enables or disables the whitelist flag on a store. Whitelisted stores appear in all province search results. Records the authenticated user in updated_by.
